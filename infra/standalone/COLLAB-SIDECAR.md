# Collab sidecar — Phase 2.3 runbook

Real-time collaborative cursors + concurrent-edit merge for Module A
section editing, via TipTap Collaboration + Yjs + a y-protocol
WebSocket sidecar.

Status: **code landed, service NOT auto-enabled**. Flip the two env
vars + enable the service when you're ready to test.

## Architecture (one paragraph)

Each `(documentId, sectionId)` pair becomes a WebSocket "room". The
client's TipTap editor mounts `Collaboration` + `CollaborationCaret`
extensions that talk to the sidecar over `wss://api.clinwrite.ai/collab/
docs/<docId>/sections/<sId>`. The sidecar maintains one `Y.Doc` per
room, relays sync + awareness messages, and persists the room's HTML
back to the API (`PATCH /documents/:id/sections/:id` with
`X-System-Token`) every 30s + once more when the last client leaves.
The API's existing content-hash check means idempotent re-POSTs of the
same HTML are cheap and don't bump the version counter.

## Pieces

| Piece | Where | Role |
|-------|-------|------|
| `apps/collab-server/` | repo | Node service (`y-protocols` + `ws`), one process per VPS |
| `platform-collab.service` | `infra/standalone/systemd/` | systemd unit (listens on 127.0.0.1:1234) |
| nginx `/collab/` block | `infra/standalone/nginx/platform.conf` | wss proxy, strips the `/collab` prefix |
| `COLLAB_SYSTEM_TOKEN` | generated by bootstrap into `/opt/platform/env/api.env` | shared secret for sidecar → API persistence |
| X-System-Token auth hook | `apps/api/src/auth/plugin.ts` | lets the sidecar PATCH sections without a session cookie |
| `useCollabProvider` + TipTap exts | `apps/web/src/screens/clinical-writing/` | client Y.Doc + WebsocketProvider + cursor rendering |
| `VITE_COLLAB_URL` | `apps/web/.env.demo` (not set yet) | flipping on client-side collab |

## Flip procedure (first time on the VPS)

1. **Pull the code** (via auto-deploy or manual):
   ```bash
   sudo systemctl start platform-deploy.service
   # or
   bash /opt/platform/repo/infra/standalone/scripts/deploy.sh
   ```
   Deploy builds `apps/collab-server/dist/` + copies the systemd unit
   into place.

2. **Confirm the secret exists in api.env**:
   ```bash
   sudo grep -c COLLAB_SYSTEM_TOKEN /opt/platform/env/api.env
   # expect: 1
   ```
   If 0, bootstrap hasn't regenerated the env since this feature
   landed. Add it:
   ```bash
   sudo bash -c "echo COLLAB_SYSTEM_TOKEN=$(openssl rand -hex 32) >> /opt/platform/env/api.env"
   sudo install -o platform -g platform -m 600 /opt/platform/env/api.env /run/platform/api.env
   sudo install -o platform -g platform -m 600 /opt/platform/env/api.env /run/platform/worker.env
   sudo systemctl restart platform-api
   ```

3. **Enable + start the sidecar**:
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable --now platform-collab.service
   sudo systemctl status platform-collab.service --no-pager -l
   ```
   Expect: `Active: active (running)` and a journal line
   `collab-server listening host=127.0.0.1 port=1234`.

4. **Confirm nginx proxies the websocket**:
   ```bash
   sudo nginx -t && sudo systemctl reload nginx
   # Smoke the proxy — expect HTTP 400 (sidecar rejects a non-WS request):
   curl -i https://api.clinwrite.ai/collab/docs/x/sections/y
   ```

5. **Flip the client env + rebuild web**:
   Edit `apps/web/.env.demo` on the repo + commit:
   ```
   VITE_COLLAB_URL=wss://api.clinwrite.ai/collab
   ```
   Next scheduled deploy picks it up and bakes it into the SPA bundle.

6. **Test in two browser windows**:
   - Open the same document in Chrome + an incognito window
   - Click Edit on the same section in both
   - Type in one — the other should see the characters appear live +
     a coloured cursor labelled with the other user's name

## Env surface (/opt/platform/env/api.env)

| Key | Required | Default | Notes |
|-----|----------|---------|-------|
| `COLLAB_SYSTEM_TOKEN` | yes | generated by bootstrap | 32-byte hex |
| `API_BASE_URL` | yes | `http://127.0.0.1:3001` | sidecar hits this for /auth/me + PATCH |
| `COLLAB_PERSIST_DEBOUNCE_MS` | no | `30000` | min interval between HTML snapshots |
| `COLLAB_PORT` | no | `1234` | where the sidecar listens |
| `COLLAB_HOST` | no | `127.0.0.1` | listen interface (behind nginx) |
| `COLLAB_SKIP_AUTH` | no | unset | **dev only** — refuses to start in prod |
| `LOG_LEVEL` | no | `info` | `debug` for connection + persistence traces |

## Rollback

If anything goes wrong, flip it off cleanly:

```bash
# Server side
sudo systemctl stop platform-collab.service
sudo systemctl disable platform-collab.service

# Client side — remove VITE_COLLAB_URL from .env.demo + redeploy.
# OR override at the live env layer without a code change:
sudo bash -c "echo 'VITE_COLLAB_URL=' >> /opt/platform/env/web.env"
# Next deploy will rebuild the SPA without collab wired.
```

Pre-existing solo-mode behaviour (textarea → TipTap WYSIWYG → Save
Section) continues working with the collab extensions off.

## Known limitations

- **No binary doc persistence**: Y.Doc state exists only while at
  least one client is in the room. Once empty + flushed, next
  re-open hydrates fresh from the HTML stored in `sections.contentHtml`.
  Fine for "same-session collaboration"; async offline edits are not
  supported.
- **No conflict resolution across section boundaries**: moving a
  paragraph between two sections is two independent edits; both can
  be winning concurrently without merge.
- **No cursor history across reload**: cursor positions are
  awareness-only (never persisted). Pressing F5 drops your cursor
  marker; the other users see you leave + rejoin.
- **Horizontal scale not supported**: `platform-collab.service` is
  single-process. Multiple sidecar instances would each hold their
  own in-memory Y.Doc for the same room → divergence. Scale with
  `y-redis` adapter when that becomes a real concern (unlikely until
  >50 concurrent editors on one document).

## Troubleshooting

### Clients can't connect

```bash
# Is the sidecar running?
sudo systemctl status platform-collab.service

# Is nginx proxying correctly?
sudo nginx -t
sudo tail -20 /var/log/nginx/platform-api.error.log

# Watch the sidecar's journal
sudo journalctl -u platform-collab.service -f
```

### Cursor renders but typing isn't syncing

Check the browser console for WebSocket errors + the sidecar journal.
The most common cause is the session cookie not reaching the sidecar
— verify `Cookie:` header is being forwarded in nginx's `/collab/`
block.

### Persistence not firing

```bash
# Check sidecar debug logs
sudo journalctl -u platform-collab.service --since '10 min ago' | grep -i persist

# Verify COLLAB_SYSTEM_TOKEN matches between sidecar + API:
sudo grep COLLAB_SYSTEM_TOKEN /opt/platform/env/api.env /run/platform/api.env
```

The two files should match. If they don't, re-run `sudo install -o
platform -g platform -m 600 /opt/platform/env/api.env /run/platform/api.env`
and restart both services.
